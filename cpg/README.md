# CPG 개발 명세

기준일 2026-11-12 · 명세 개정 2 · 구현 전 기준안

CPG는 과목 추천과 시간표 설계를 각각 제공한다. 학생은 추천 과목과 이유를 보거나 시간표 화면에서 바로 여러 후보를 만들 수 있다. 시간표는 과목을 지정하지 않아도 대상 학기의 개설 목록으로 생성한다. 추천 화면에서 담아둔 과목은 학생이 원할 때 시간표 조건으로 추가한다. 수강신청 실패 후에는 이미 확보한 분반을 유지하면서 재조합한다. 첫 지원 대상은 서울과기대 컴퓨터공학과 2021~2026 입학, 주간·일반 신입학·단일전공 과정이다. 그 밖의 학생도 입력을 저장할 수 있고 요건 계산에서는 지원 범위를 명시한다.

## 서비스 경계

브라우저는 같은 출처의 CPG 백엔드만 호출한다. 백엔드 한 프로세스 안에서 모듈을 함수로 호출하며 공식 자료 배치는 검수된 JSON 파일로 적재한다. 모듈 경계의 JSON 규약은 함수 호출·파일·테스트에서 같은 의미를 가진다.

[모듈별 JSON 입출력과 SQLite 접근 파이프라인 이미지](cpg-data-pipeline.png)

| 사용자 기능 | 입력 | 출력 |
| --- | --- | --- |
| 학생 입력 | 입학연도·학과·학년·입학 유형·대상 학기·희망 학점·관심 태그, 공유 링크 또는 수동 이수내역 | 검토 가능한 과목과 경고, 저장 리비전, JSON 내보내기 |
| 과목 추천 | 학생 입력 리비전, 확인된 과목, 공식 규칙과 대상 학기 강좌 | 충족·미충족·확인 필요 요건, 추천 과목·이유·수강 자격, 과목 저장 |
| 시간표 설계 | 학생 입력 리비전, 대상 학기의 공식 개설 목록, 수업 불가 시간·요일, 학점 범위, 수업 언어·정렬 기준, 선택 사항인 필수·선호 과목 | 여러 과목·분반 조합, 학점·등교일·공강 지표, 조합 불가 또는 검토 필요 이유 |
| 신청 실패 대응 | 기준 후보, 확보한 분반, 실패한 분반, 허용한 대체 과목 | 대체 시간표와 유지·교체·누락 분반, 대체로 달라진 예상 요건 |

## 근거와 현재 구현

- [Notion CPG 기획 및 파이프라인](https://app.notion.com/p/2026-EndPoint-40f3f86cd5c380b5813ef06cc0fbcaae)에는 공통 학생 JSON 예시, 과목 추천, 시간표 플랜, 공개 시간표 조회 샘플이 있다. 서비스는 과목 추천 화면과 시간표 플랜 화면을 별도로 둔다.
- [team20 상세 설계](<C:/Users/김재민/Desktop/team20/sources/course_planning_design.md>)와 [요건 검수 메모](<C:/Users/김재민/Desktop/team20/sources/review_notes.md>)를 규칙·매칭·검수의 출발점으로 사용한다. 현재 입력 앱은 `source=everytime`을 거부하며 해당 강좌코드·교수·원본 참조를 저장하지 않는다.
- [학교 개설과목 수집기](../../seoultech_class/README.md)와 2026-2 컴퓨터공학과 CSV 40행이 있고, [건물 거리](../../seoultech_class/classroom_dist/README.md)는 별도 데이터로 있다. 이 자료를 연결하는 CPG 적재 모듈은 새 작업이다.
- [화면 프로토타입](../../endpoint-prototype.html)은 내장 예시 데이터로 동작하며 시간표 생성에 과목 선택을 요구한다. 과목 없이 생성하는 경로와 저장 과목 조건 추가는 개정 2의 구현 항목이다.

## 문서 관리

이 폴더를 구현 기준으로 사용한다. 규약이나 저장 정책을 바꿀 때는 해당 명세, 영향 받는 예시·호환성, [작업 기록](04-decisions-and-work.md)의 날짜·결정·검증 결과를 같은 변경으로 갱신한다. 프로토타입 동작과 실제 데이터 검증은 각각의 근거를 기록한다. 추후 기계 검증용 스키마와 OpenAPI를 추가할 때 Markdown의 규약과 함께 갱신한다.
