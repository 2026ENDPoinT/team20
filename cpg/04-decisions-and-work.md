## 2026-11-13 · 추천 알고리즘 설계 제안

과목별 요건 기여를 순위로 보여주고, 시간표는 독립 요청에서 분반 조합을 탐색하는 방향을 제안했다. 초기 구현은 대표 학번과 검수된 분반 묶음에서 가지치기 백트래킹을 사용하고, 한 학기 규모에서 탐색 성능을 측정한다. 실제 CSV의 교시 충돌 예시를 확인했으며, 수강 자격과 선수과목 자료는 검수 작업으로 남아 있다. [추천 알고리즘 설계안](05-recommendation-design.md)

과목 추천과 시간표 설계를 두 독립 HTML로 시험 구현했다. 실제 CSV에서 과목 미지정 시간표 생성, 불가 요일·학점 범위·충돌 검사, 이수 과목 제외, 실패 분반의 같은 과목 대체를 확인했다. 12~15학점 예시는 100,000노드 제한 안에서 후보 다섯 개를 반환했다. [테스트 구현 및 검증](05-recommendation-design.md#테스트-구현)

HTML을 직접 열면 브라우저가 로컬 CSV 요청을 제한하는 실행 경로를 수정했다. 파일로 열 때는 CSV에서 생성한 브라우저용 사본을 사용하고, 실행.cmd는 두 테스트 페이지를 기본 브라우저에서 연다. [테스트 실행 방법](../../seoultech_class/timetable_lab/README.md#실행)

수강 사진 3장의 19건을 2023학번·2학년의 기본 이수내역으로 연결했다. 과목 기준 중복을 제외한 18개를 추천과 시간표 생성에 반영하고, 2학년 권장 전공과 학번별 남은 교양요건을 적용했다. [비교용 샘플](05-recommendation-design.md#2학년-실데이터-비교용-샘플)

| 마지막 20% | 통합과 리허설에 집중한다. 새로 실행해 학생 저장 → 시간표 직접 생성 → 실패 대응을 시연하고, 별도로 과목 추천을 보여준다. 시연용 데이터·실행법·막힌 항목을 기록한다. |

공용 서버의 라우팅과 DB 스키마 변경은 팀원이 모으고, 김재민은 개설강좌 변환·시간표 계산·시간표 화면을 맡는다. 첫 통합 이후에는 두 기능이 같은 SQLite의 검수된 분반 스냅샷을 읽는다. 현재 HTML 프로토타입은 두 화면이 한 파일에 있으므로 동시에 편집해야 하면 초반에 각 화면의 로직을 별도 파일로 옮기거나 한 사람이 통합한다.

시간이 남으면 저장 과목을 시간표의 선호 조건으로 적용하는 경로를 추가한다. 에브리타임 자동 가져오기와 과거 강좌 전수 매칭은 확인된 이력으로 추천이 동작한 뒤 진행한다. 이동거리·잔여석·여러 학기 계획은 후속 범위다. 학교 교시표나 공식 코드 대응이 준비되지 않으면 시연용 자료임을 표시하고, 검증된 자료 범위와 차이를 기록한다.

## 2026-11-12 · 명세 개정 2

- 과목 추천과 시간표 설계를 독립 진입점으로 결정했다. 개정 1의 선형 화면 흐름을 이 결정으로 대체한다.
- `schedule_request`는 `input_revision`과 시간표 제약으로 직접 실행한다. `selections`를 생략하거나 빈 배열로 보내면 대상 학기 개설 목록에서 과목·분반을 자동으로 채운다. 추천 결과의 ID를 시간표 요청에 전달하던 설계를 제거했다.
- 사용자가 저장한 과목을 다시 볼 수 있도록 `saved_course`, `saved_course_list`, `/api/v1/saved-courses`, `saved_courses` 테이블을 추가했다. 시간표 화면에서 선택한 과목을 필수 또는 선호 조건으로 전달한다. 저장 과목을 가져올 때 기본값은 선호다.
- 시간표 재조합에 명시한 대체 과목은 대상 학기 개설 목록과 자격 조건으로 검증한다. 시간표의 실행 맥락과 저장 계획에는 당시 적용한 제약을 남긴다.
- Markdown과 [파이프라인 이미지](cpg-data-pipeline.png)를 갱신했다. API와 화면 구현은 아래 작업에 남아 있다.
- 강좌는 학기별 검수본을 SQLite에 저장해 조회하고 학교 공개 시간표는 수집·갱신에 사용하기로 했다. MVP는 수동 갱신으로 시작하며 자동 갱신 주기는 운영 조건 확인 후 정한다. [개설강좌 조회와 갱신](03-data-storage.md#개설강좌-조회와-갱신)

## 구현 순서와 완료 기준

| 순서 | 상태 | 작업 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 대기 | 학생 문서 v2와 SQLite 이행, JSON 계약 검증 | 기존 저장 데이터와 ID 복구, 버전 충돌·이행 실패 롤백, 내보내기/재로딩 |
| 2 | 대기 | 에타 수집 UI·작업·적용 | 실제 공개 샘플의 전체/부분 성공, 재수집 중복 방지, 미확인·확인 상태 보존 |
| 3 | 대기 | 공식 데이터 JSON 변환·교시 확보·SQLite 적재 | 데이터셋·매니페스트 검증, 참조 무결성·0행 범위·실패 복구 |
| 4 | 대기 | 학기+강좌코드 매칭·이수요건 계산 | 복수·누락·충돌 처리, 중복·택1·미완전 이력·편입 범위 테스트 |

| 7 | 대기 | 계획 저장, 복원·삭제, 통합 데모 | 입력부터 저장된 계획 복구까지 한 경로, 이전 데이터 버전 표시, 삭제 후 재요청 차단 |

1~2와 3은 입출력 규약을 공유하며 병행할 수 있다. 5와 6은 공통 데이터·계산을 기반으로 별도 구현한다. 구현 시 [OpenAPI](https://spec.openapis.org/oas/v3.1.1.html)와 [JSON Schema](https://json-schema.org/draft/2020-12) 파일을 계약 테스트와 함께 추가한다. 이 문서의 Markdown은 결정 근거와 운영 변경 기록으로 유지한다.

## 계약 테스트에 넣을 시나리오

| 영역 | 입력과 기대 결과 |
| --- | --- |
| v1 → v2 | 과목 ID와 유효한 확인 상태 유지, 과거 수업 일정은 복구 백업에 존재, 없는 코드는 `null` |
| 가져오기 | 성공 1학기·실패 1학기는 부분 결과. 같은 링크를 다시 가져와도 미수정 행의 확인 유지. 원본 식별 필드 변경 수락 후 확인 해제 |
| 데이터 발행 | 학과/학기 혼합, 중복 키, 잘못된 해시, 요건 참조 순환의 경우 활성 버전 유지 |
| 강좌 연결 | 앞자리 0인 전체 코드 단일 일치 성공. 복수 후보·교수나 명칭 충돌·미조회 학기는 확인 대기 |
| 요건 계산 | 택1 두 과목 이수는 필수 충족 한 건, 학점 인정은 규칙별 계산. 미확인 이력의 부족 판정과 실제 미충족을 구별 |
| 추천 | 확정 자격 위반 분반 제외, 제한 미확인 이유 표시, 과목 단위 중복 제거 |
| 독립 계획 | 과목 추천을 호출하지 않은 세션에서 `selections` 생략과 `[]`로 시간표 생성. 학점 범위·불가 시간에 맞는 과목과 분반을 자동 편성 |
| 저장 과목 | 목록에 저장만 한 과목은 선호 조건에 추가하지 않음. 사용자가 골라 보낸 과목만 필수·선호 조건으로 적용. 목록을 바꿔도 저장한 계획의 제약은 유지 |
| 계획 | 고정·실패 분반 중첩 오류, 정확히 이어진 수업 허용, 시간 미확인 분반 제외, 언어 불일치 제외 |
| 계획 실패 | 조건 충돌이 확정이면 `no_feasible_plan`, 자료 누락 또는 후보 없는 시간 초과는 `undetermined` |
| 버전과 삭제 | 오래된 ETag는 `412`, 공식 버전 교체 후 기존 실행은 `409`, 저장안은 과거 버전으로 조회, 학생 삭제 후 개인 캐시 접근 불가 |
